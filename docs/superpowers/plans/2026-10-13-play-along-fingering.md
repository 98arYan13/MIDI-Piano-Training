# Play Along Automatic Fingering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Generate accurate local research-model fingering for a selected library MIDI song, persist it per note, and display it on the existing score with Full/Medium/Pro density and optional manual corrections.

**Architecture:** A project-local Python/PyTorch ArGNN worker performs inference on demand. C++ owns its job lifecycle, validates results, and saves assignments atomically to existing song JSON in SQLite. React/VexFlow adds annotations without changing musical notation or reloading playback.

**Tech Stack:** Existing C++20/CMake/LLVM-MinGW, cpp-httplib, nlohmann JSON, SQLite, React/TypeScript/VexFlow 5.0.0, Catch2/Vitest/Playwright; local CPython 3.11.9 and CPU PyTorch 2.8.0 as initial reproducible compatibility targets.

**Spec:** `docs/superpowers/specs/2026-10-13-play-along-fingering-design.md` (approved 2026-10-13).

## Global Constraints

- Native C++ continues to own audio, MIDI, playback, scoring, MIDI song import, and persistence.
- Keep the existing left/right score notation. Do not move notes between staves, change clefs, pitch spelling, rhythm, voice allocation, ties, beams, or track assignments. Add finger-number annotations to the existing engraving.
- Full, Medium, and Pro change the number of visible tips without changing saved assignments.
- Fingering-file import, MusicXML import for fingerings, and fingering JSON import are excluded.
- Missing/incompatible weights are a feature setup error, not permission to silently substitute rules or random fingers.
- No retraining, training datasets, cloud inference, or GPU requirement is part of this design.
- Only one generation job runs at a time, and completed jobs release the worker.
- Use a 30-second inactivity timeout for worker messages and a 15-minute total job limit.
- Use bounded overlapping windows of at most 256 notes per hand, with 64 notes of context from the preceding window. Prefer boundaries at rests and never split a simultaneous chord.
- Keep runtimes, caches, downloaded dependencies, and checkpoint files in ignored project-local paths and out of Git.
- Never run or request graphify update. Retain project tests; remove only disposable diagnostics created in this execution.
- Preserve sounding live voices and global monitoring/click ownership; no audio-engine reset or transport reload for fingering operations.
- User-selected execution overrides the older AGENTS.md model rule for this work: parent requested `gpt-6.1-sol` / `low`; EVERY child implementer, fixer, task reviewer, and final reviewer uses `gpt-6-luna` / `medium`. No escalation, no worker/reviewer spawning. Use the available fast service tier if the dispatch interface exposes it; do not claim a tier was set when no such parameter exists. The parent model cannot be changed through the available agent tools.
- Apply Ponytail: reuse the existing library, preference, event-window, and test paths; no extra web service, inference framework, general plugin architecture, or speculative UI.

## Review Focus

1. Switching songs during generation must save only to the job's original song and must not show the previous song's result on the new song (Tasks 3, 5).
2. A manual correction, relevant track edit, or trash operation during inference must invalidate stale results without deleting previously saved fingerings (Tasks 2, 3).
3. A renamed track or mixed MIDI track must use the existing renderer's exact hand grouping while leaving notation and assignments untouched (Tasks 2, 4).
4. A duplicate unison, held inner voice, or tied note across an inference/score-window boundary must retain correct identities, digits, and single-attack labels (Tasks 1, 4).
5. Missing/corrupted weights, broken worker framing, cancellation, timeout, or shutdown must leave the library usable and release owned worker processes (Tasks 1, 3, 6).

## File Responsibilities and Shared Contracts

- `fingering/model.py`: minimal attributed model architecture, checkpoint loading, preprocessing, graph edges, constrained beam decoding, and bounded windows. `fingering/worker.py`: framed stdin/stdout protocol and progress only.
- `fingering/dependencies.json`, `fingering/requirements.lock`, `scripts/setup-fingering.ps1`: exact revision/runtime/wheel/checkpoint pins and project-local setup. Populate real checksums during Task 1; placeholders must not enter a commit.
- `native/include/sightreading/FingeringData.hpp`, `native/src/FingeringData.cpp`: hand resolution, fingerprinting, tip categories, and result validation. Existing `Storage`/`Library.cpp`: atomic save/manual editing.
- `native/include/sightreading/FingeringJobs.hpp`, `native/src/FingeringJobs.cpp`: one-job manager. `native/include/sightreading/FingeringProcess.hpp`, `native/src/FingeringProcess.cpp`: owned Windows child process/pipes only. Existing routes/service wire the manager without changing transport.
- Existing `notationModel.ts`, `types.ts`, `scoreModel.ts`, `EngravedScore.tsx`: annotation types, identity propagation, and rendering. New `web/src/FingeringControls.tsx`: generation status/settings/manual-edit UI used by `PlayAlong.tsx`.
- Existing package/notice scripts and guide: ship the pinned inference runtime and explain only user-visible controls.

Wire protocol version is `1`: four-byte unsigned little-endian UTF-8 JSON byte length followed by that JSON. Cap any frame at 256 MiB; reject oversized frames with an actionable error without changing saved data. Diagnostics use bounded stderr, never stdout. Native requests are `{version,jobId,songId,fingerprint,ppq,notes}`; each eligible note is `{id,midiNote,startTick,endTick,hand,manualFinger}` with `manualFinger` null or 1–5. Timing is original PPQ ticks. Worker frames are `{version,jobId,type:"progress",stage,completed,total}`; final `{version,jobId,type:"result",assignments,model}`; failure `{version,jobId,type:"error",code,message}`. `assignments` entries are `{id,finger,hand,reason?}` with `finger` null or 1–5. `model` is `{name:"ArGNN",revision,checkpointHashes:{left,right}}`.

Persist `note.fingering = {finger,hand,source,tips,reason?,automaticFinger?}`. Sources are `generated` or `manual`; tips are `phraseStart`, `thumbCrossing`, `positionChange`, `majorPositionChange`, `difficultChord`. Store `song.fingeringRun = {model,generatedAt,fingerprint,assigned,unresolved,unsupported}` and `song.fingeringRevision`, initially 0. Default settings field is `preferences.fingeringTips = "medium"`; permitted values `full`, `medium`, `pro`. Missing fields remain compatible with old songs/settings.

Job states are `idle`, `running`, `completed`, `cancelled`, `failed`. `JobSnapshot` JSON contains `{state,jobId,songId,stage,completed,total,error?,summary?}`; no note arrays. Endpoint errors use the existing `{error:{code,message}}` shape. Polling never changes musical transport state.
