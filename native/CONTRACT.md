# Native engine contract (version 1)

`Engine.hpp` is the service boundary. Constructing the default Engine does not load piano assets. Register hooks before `start()`, then start WASAPI and the asynchronous piano loader. Serve HTTP immediately; poll `snapshot()` for `pianoLoading`, `pianoReady`, `audioReady` and `error`. `pianoReady` follows validated sample decoding/preloading, never a timer. Audio clock/input state can operate while the piano is unavailable. `preloadSynchronously=true` is intended for offline rendering/tests.

Commands use `{version:1,id,type,params}` and return `{version:1,id,ok,result,error}`; errors have stable `code` and `message`. Types: `status`, `panic`, `virtual.noteOn`, `virtual.noteOff`, `virtual.pedal`, `virtual.disconnect`, `bus.stop`, `devices.enable`, `audio.settings`, `audio.applyPending`. Virtual events accept `source` (stable string), `channel` (0–15), `instance` (nonzero unique note token); noteOn also takes `note` (21–108), `velocity` (1–127). Pedal uses `down`. `bus` is `live`, `playback`, or `example`; stopping live returns `protected_bus`. Inspect Commands.cpp for field validation and stable failure replies. Device enable takes `id` and `enabled`. Settings include volume, monitoring, outputMode (`internal`, `external`, `silent`), velocityCurve, channels, outputDevice, exclusive and externalDevice. Device/mode changes defer while live keys/pedals are held; applyPending `applyNow=true` explicitly interrupts them.

Snapshot includes heldNotes with source/channel/instance/bus/held/sounding/sustained, device identities, recent raw MIDI monitor messages, requested/actual WASAPI format and API output latency. Held physical keys remain distinct from sustained sound. `overload` includes event pressure and sampler allocation refusal; `voiceRefusals` counts each failed physical allocation, including partially admitted multilayer attacks and releases. The live sampler physically contains 1,024 voices with 960 attack capacity and 64 release reserve. Playback and examples have independent 256-voice pools. No allocator steals or reuses releasing voices. The checked-in patch and compile-time capacity assertion prevent silently compiling the stock 256-voice limit.

`submit(InputEvent)` supports absolute native sample-frame timestamps. Zero schedules at the next render block. The fixed scheduler preserves stable order; stopping a bus or disconnecting a source invalidates its queued attacks. Queue release pressure triggers source-scoped recovery. Source slots 126/127 are reserved for integration/test input; named command/device sources occupy 1–125. A failed attack never generates an untargeted note-off. Channel filtering rejects attacks and permits releases.

`render(float* interleavedStereo,unsigned frames)` is the single audio-consumer offline path; do not call it concurrently with WASAPI. InputHook receives applied events with exact absolute frame positions. RenderHook adds click/other native audio into the stereo buffer after the three sampler buses, before volume/limiter. Later controllers compose their functionality behind the one hook of each kind. Hooks must avoid allocation, blocking, locks and IO; their contexts must outlive Engine, including destructor Panic. Explicit Panic/stop notify InputHook with Panic; navigation and exercise stops must use their owned bus and leave global live/click state running.

MIDI inputs are enumerated/opened/reconnected globally every 250 ms. WASAPI requests 48 kHz/128 frames and reports the actual stream status. The render callback uses bounded preallocated application storage; sfizz streams sample tails through its own workers. External MIDI sends are native RtMidi messages; external instrument polyphony and MIDI 1.0 ownership behavior require hardware validation and cannot inherit the internal sampler's allocation guarantee. Physical reconnect, MIDI-to-audio p95 and a long-session dropout soak remain hardware acceptance checks.

Virtual source names beginning with `midi:` are rejected before allocating or resolving source IDs; that namespace belongs exclusively to native device identities. External monitoring disabled suppresses new attacks and pedal-down ownership, while note-off, pedal-up, source disconnect and Panic retain their release paths. `setExternalMessageHook` registers a stopped-only native delivery sink for embedding/tests and overrides RtMidi delivery while present. It runs on input/control producer threads under the external routing mutex, never in the audio callback. Its context must outlive Engine; it must not reenter Engine or throw. This sink observes the production routing decisions without substituting piano rendering.

## Global native metronome (version 1)

Commands `metronome.config`, `metronome.start`, `metronome.stop` run through the Engine control mutex into a bounded 63-command native queue. Full queues fail without changing requested settings. `snapshot().metronome` exposes requested canonical settings, running, activeTempo, activeMeter, beat and bar; its `settings` object excludes transient running/position and is the Task3 persistence boundary. Settings: mode `independent`/`follow`, tempo 20–300 quarter-note BPM, meter {numerator:1–12,denominator:2/4/8/16}, subdivision `quarter`/`eighth`/`sixteenth`/`triplet`, per-beat accents `strong`/`weak`/`mute`, swing 50–75, countIn 0–4, sound `click`/`woodblock`/`rim`, volume 0–1 and mute. Beat unit is the meter denominator (6/8 has six eighth beats); subdivision names represent 1/2/4/3 equal divisions of that beat unit, with swing applied to paired divisions. Tempo is explicitly quarter-note BPM, making denominator conversion unambiguous.

Start is idempotent while running; otherwise the next render block begins beat zero immediately. Count-in is audible and marked in beat events for the first configured number of bars, then continuous clicks continue without a gap. No silent startup delay. Tempo edits apply at the next beat; meter/subdivision/swing/accents/count-in at the next bar. Volume/mute/sound apply at the next beat. Changes never rebuild audio or reset the native sample frame. Click samples are original three short synthesized percussion waveforms generated at construction, before the audio callback; sixteen independent preallocated voices mix into stereo ahead of the existing master volume/limiter, without piano ducking or voice sharing. Click stop cancels click tails only; piano bus stops and source disconnects leave clicks running; Panic and Engine shutdown cancel clicks.

`setBeatHook` is stopped-only; its callback receives exact absolute frame/bar/beat/subdivision/countIn events from the audio consumer. Hooks must not allocate/block/lock/do IO and contexts must outlive Engine destructor Panic, as for existing hooks. `followMetronome(quarterBpm,numerator,denominator,beat,absoluteFrame)` is a control-thread Follow adapter: Independent ignores updates; Follow queues a native resynchronization at that position (past positions clamp to the next render block). A transport stop deliberately sends no stop command; metronome retains its last tempo/meter and keeps running. Only explicit metronome.stop/Panic ends it. Later transports call this adapter for start/seek/tempo-map changes; no browser sound scheduling is involved.

Review fixes: Panic captures the current monotonic metronome command boundary in its native input event. It cancels commands/resyncs up to that boundary while preserving later commands, including a Start submitted before the next render. Future Follow updates reserve one of 63 bounded slots and enter a stable frame-ordered preallocated schedule; the current clock continues until each target frame. Same-frame updates apply in producer order. Queue/schedule exhaustion fails before changing requested settings. Persisted `beatUnit` is accepted only when it matches the saved meter denominator, so `metronome.settings` round-trips directly through metronome.config.

Scheduled Follow updates affect transport tempo/meter/position only. They preserve independent sound/volume/mute/subdivision/accent settings and leave pending next-bar edits intact. Explicit tempo or meter configurations submitted after a Follow reservation take precedence over its captured values using per-field native command revisions.
## Local native service and browser contract (version 1)

Build target `sightreading`, Windows executable `build/native/native/sightreading.exe`. It accepts `--port` (default8765), `--data-dir` (default LOCALAPPDATA/SightReading), `--web-dir` (default web/dist). Serve HTTP immediately while async sample preload runs. The process owns audio/MIDI/metronome; browser close is not process shutdown. Signal/Ctrl+C stops it; launcher prints PID for explicit Stop-Process. Final tray/release lifecycle remains Task8.

One listener bound127.0.0.1 serves self-hosted assets, HTTP and WebSocket. Exact Host and any supplied Origin must match `127.0.0.1:<port>` / `http://127.0.0.1:<port>`; mutation/WS upgrade additionally require Origin. Duplicate Host/Origin rejected. No wildcard CORS. Hostile WS Origin rejected before101. HTTP body limit20MB; actual MIDI importer/remaining song CRUD is Task6.

HTTP GET `/api/v1/status` gives full native snapshot plus `generation` and monotonic `engineTimeNs`; GET `/devices` gives inputs/midiOutputs/audioOutputs; GET `/settings` gives currently applied audio settings; PUT `/settings` accepts an audio-settings object; GET `/metronome`; POST `/command` uses the standard versioned envelope. Invalid JSON is400, origin errors403, valid command errors use standard `ok:false` envelopes. GET `/songs` lists nontrashed song identities; `/songs/{id}` and `/songs/{id}/events` return404 until a song exists. SQLite schema1 includes settings and song model/title/trash foundations. Newer schema versions fail rather than silently downgrade.

WS `/api/v1/events` accepts the same command envelope, replies with request IDs and pushes `{version:1,type:'snapshot',generation,state,events,eventDrops,resync}` at30Hz. `state` is always authoritative. Events are `{sequence,type:'note'|'beat',event}`. Note event kind0/1/2/3/4/5/6=on/off/pedal/disconnect/stopBus/Panic/resetLive; bus0/1/2/3=live/playback/example/click. Applied note/beat frames are exact native frames. Bounded single-producer rings capture events without allocation/locks/IO in callbacks; control worker drains to a512-event history. `eventDrops` counts ring overflow. Initial reconnect and history gaps set `resync`; browser rebuilds from full state and discards stale event history. Snapshots contain sampleFrame/sampleRate; `clock.ping` returns full timestamped state for round-trip midpoint offset estimation. Frontend extrapolation is visual only and capped250ms; no audio scheduling.

A maximum32 simultaneous browser connections own reusable `browser:slot:N` native source identities. Caller virtual source names are mapped to the connection owner; reserved `midi:` names remain rejected. A connection's virtual commands therefore share a source and require unique note instance tokens across its inputs. Disconnect submits that source's release before returning its slot, preserving physical MIDI and other browser connections. Slots reuse stable names, avoiding exhaustion of native named sources after repeated reloads. Source names returned in heldNotes are these service identities rather than the caller alias.

`EngineOptions.disabledInputs` restores persisted disabled identities before native discovery, so a saved disabled device is not first opened and then disabled. Snapshot `disabledInputs` is an identity→disabled map including absent devices. `externalPortOpens` is a diagnostic lifetime count: ordinary audio.settings keep the selected external output open. Only actual WASAPI outputDevice/exclusive changes rebuild the stream; output mode/monitoring/external-port changes retain existing live-held deferral but do not reset the native clock. Actual device rebuild/physical MIDI reconnection remain hardware acceptance checks.

Persistence saves accepted requested audio settings (pending changes included), canonical metronome.settings, and disabled native MIDI identities. Each replacement is an atomic SQLite statement; schema migration is transactional/WAL. Transient held notes, metronome running/position and transport state are not restored after process restart. Browser reload restores current live native state instead of issuing any stop/reset/config command. Hooks/controllers should extend this service's bounded capture path; do not replace existing render/input/beat hooks without composing their owners.

Frontend contracts are frozen in `web/src/types.ts`; `NativeProvider` wraps the entire app, `useNative()` exposes the shared NativeClient, `.command(type,params)` returns a promise, `.state` is the native snapshot, `.frame()` is the native-clock visual estimate and `.events` contains the current event batch. NativeClient never retries mutating commands automatically. Global toolbar z1200; global settings z1100; future route dialogs should stay below that. Fullscreen targets document root. Shared keyboard/notation/practice pages are Tasks4–7.

ApplyNow reserves a live-bus generation and queues ResetLive (kind6), including external live note-off/pedal-up ownership. The audio consumer clears only live sampler/state/pedals, emits the input hook, and retains playback/example schedules and metronome. Queue pressure uses an atomic reserved reset-generation recovery before dispatching scheduled new attacks. A short reconfiguration gate rejects new live attacks/pedal-down until reset reservation/settings application finish; releases retain their path. Ordinary settings ApplyNow keeps the stream; actual device/exclusive rebuilds can produce an audio gap and have not been hardware-certified.

Convenience commands `metronome.meter` accepts only optional numerator/denominator and `metronome.accent` requires zero-based beat + strong/weak/mute accent. Both merge canonical requested state under the existing Engine control mutex, validate through metronome.config, and persist canonical settings. They prevent rapid independent UI edits from overwriting stale30Hz composite state. Accent-only edits do not change meter revisions/Follow reservations. Numeric tempo/beats fields keep local uncommitted text drafts while focused; valid edits commit on blur/Enter, committed/running state stays native-authoritative.
Atomic `audio.channel` accepts only channel0–15 and boolean enabled, merging canonical applied/pending channels under the existing control mutex before audio.settings validation/persistence. This prevents rapid independent checkbox edits from losing another channel change.
